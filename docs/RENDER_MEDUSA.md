# Deploy Medusa (API + Admin) on Render

Repo: `umami-restaurant` → Blueprint uses `render.yaml` at the repo root.

## What you get

| Resource | Name | Role |
|----------|------|------|
| Web (Docker) | `umami-medusa` | Medusa API + Admin (`/app`) |
| Postgres | `umami-postgres` | Database |
| Key Value | `umami-redis` | Redis for sessions |

Admin URL after deploy: `https://umami-medusa.onrender.com/app`  
Health: `https://umami-medusa.onrender.com/health`

## 1. Deploy Blueprint

1. Open [Render Dashboard → Blueprints](https://dashboard.render.com/blueprints)
2. **New Blueprint Instance** → connect `redaalmajed/umami-restaurant`
3. Confirm `render.yaml` is detected → apply
4. Wait until Postgres + Redis + web service are green

Plans in `render.yaml` use **starter / basic** (paid). Free tiers sleep and break Admin; upgrade if needed.

## 2. Fill sync:false env vars (Dashboard → umami-medusa → Environment)

Replace with your real URLs after the first deploy gives you `https://umami-medusa.onrender.com`:

```env
MEDUSA_BACKEND_URL=https://umami-medusa.onrender.com
ADMIN_CORS=https://umami-medusa.onrender.com
AUTH_CORS=https://umami-medusa.onrender.com,https://YOUR_STORE.vercel.app,http://localhost:8000
STORE_CORS=https://YOUR_STORE.vercel.app,http://localhost:8000
STOREFRONT_REVALIDATE_URL=https://YOUR_STORE.vercel.app/api/revalidate
```

Secrets (`JWT_SECRET`, `COOKIE_SECRET`, …) are auto-generated by the Blueprint.

**Redeploy** the web service after saving CORS / `MEDUSA_BACKEND_URL` (Admin embeds backend URL at build — set `MEDUSA_BACKEND_URL` as a Docker build arg on next push if Admin calls wrong host).

## 3. Create Admin user (one-time)

In Render → `umami-medusa` → **Shell** (workdir `/server`):

```bash
./node_modules/.bin/medusa user -e you@example.com -p 'ChooseAStrongPassword'
```

## 4. Seed Umami menu

```bash
cd /server
./node_modules/.bin/medusa exec ./src/scripts/seed-restaurant-commerce.ts
./node_modules/.bin/medusa exec ./src/scripts/seed-umami-menu.ts
```

Copy the publishable API key from Admin → Settings → Publishable API Keys into Vercel storefront env:

```env
NEXT_PUBLIC_MEDUSA_BACKEND_URL=https://umami-medusa.onrender.com
NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY=pk_...
```

## 5. Link storefront (Vercel)

See `docs/VERCEL_STOREFRONT.md`. Use the same `REVALIDATE_SECRET` on both sides.

## Manual create (no Blueprint)

1. Create Postgres + Key Value in Frankfurt (same region as web)
2. Web service → Docker  
   - Dockerfile path: `apps/backend/Dockerfile`  
   - Context: repo root `.`
3. Health check: `/health`
4. Env: same as Blueprint section above + `DATABASE_URL` / `REDIS_URL` from the managed services

## Local notes

- `REDIS_URL` optional locally; required on Render for production sessions
- `MEDUSA_WORKER_MODE=shared` = one service handles HTTP + jobs (fine for trial)
- Later: split worker service with `MEDUSA_WORKER_MODE=worker` + `DISABLE_MEDUSA_ADMIN=true`
